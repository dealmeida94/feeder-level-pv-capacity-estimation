2. Descrição dos scripts

2.1. processamedicoes.py

Processa os dados originais disponibilizados por Bu et al., garantindo a formatação das datas no padrão datetime,e as medições para tipo numérico. Além disso, realiza verificações nos dataframes em busca de inconsistências.

Os dados correspondem a uma rede de distribuição real composta por 3 alimentadores, aos quais estão conectados 1120 consumidores. Todos os consumidores são equipados com smart meters que registram o consumo horário de energia (kWh). O conjunto de dados disponibilizado contempla 1 ano de medições.

Para preservação da privacidade dos consumidores, as medições dos smart meters são agregadas no nível secundário dos transformadores de distribuição,

formando nós (buses). Ao todo, o sistema é composto por 240 nós. A potência reativa da rede foi determinada por meio da atribuição de fatores de potência aleatórios aos nós (buses), no intervalo de 0,90 a 0,95. A metodologia de cálculo utilizada está descrita na planilha de dados disponibilizada pelos autores.

Referência: F. Bu, Y. Yuan, Z. Wang, K. Dehghanpour, and A. Kimber, "A Time-series Distribution Test System based on Real Utility Data." 2019 North American Power Symposium (NAPS), Wichita, KS, USA, 2019, pp. 1-6. https://wzy.ece.iastate.edu/Testsystem.html

ENTRADA:

  • arquivo "Calculated Nodal P&Q.xlsx" : arquivo original disponibilizado pelos autores.

SAÍDAS:

  • arquivo "NodalPQprocessado.xlsx" : dados após processamento;

2.2. geraloadshapes.py

Realiza uma leitura da planilha 'NodalP&Qprocessados.xlsx' e gera os arquivos .txt contendo os loadshapes de potência ativa em p.u (normalizados por unidade) por bus, e também os arquivos loadshapes.dss que criam as cargas no OpenDss e apontam para os .txt

Etapas do processo:

  1. Leitura dos dados
  2. Eliminação das cargas nulas
  3. Para cada bus, estabelece o valor máximo da série como potência de base
  4. Realiza a normalização da série
  5. Salva a série normalizada (loadshapes) em arquivos .txt, sendo um para cada bus
  6. Gera o arquivo Loadshapes.dss para cada Feeder
  7. Salva os valores de base adotados em uma planilha para possibilitar a conferencia.

INPUTS:

  • planilha 'NodalPQprocessados.xlsx'

OUTPUTS:

  • arquivos .txt com o loadshape de cada bus. Padrão do nome do arquivo: FeederXBusxxxx.txt | Ex.: FeederABus1003.txt (arquivos são separados por Feeder)
  • arquivo Loadshapes.dss para cada Feeder. Padrão do nome do arquivo: LoadshapesFeederX | Ex.: LoadshapesFeederA.dss
  • arquivo .csv contendo os valores de base adotados. Padrão do nome do arquivo: ValoresdeBaseFeederX.csv | Ex.: ValoresdeBaseFeederA.csv
  • relatório: loggeraloadshapes.txt

2.3. extraidadosLoaddssoriginal.py

O arquivo Load.dss original considera cargas estática e, portanto, é necessario a crição de um novo arquivo Load.dss que considere os loadshapes das cargas.

Para isso, é preciso conhecer o as configurações (nome, numero de fases e tipo de conexão) de cada carga.

Para tal, o script realiza a leitura linha a linha do arquivo "Load.dss" original e, por meiod de buscas de padrões de texto (expressões regulares/regex) identifica as configurações de cada carga e salva-as em uma arquivo .xlsx.

INPUTS:

  • Arquivo Load.dss original: 'LoadOriginal.dss'

OUTPUT:

  • Arquivo de configurações dos loads: 'configsdoload.xlsx'

2.4. geraarquivoLoaddss.py

Gera três arquivos Load.dss, sendo um para cada Feeder, com base nas configurações extraídas para cada feeder, nos loadshapes e valores de base definidos durante a construção dos loadshapes.

INPUTS:

  • planilha .xlsx contendo as configurações do feeder;
  • planilha .csv contendo os valores de base adotados;
  • arquivos loadshapes.dss.

OUTPUTS:

  • Arquivos Load.dss por feeder;
  • Relatório com inconsistências em .xlsx.

2.5. geramasterdss.py

Tendo por base o arquivo Master.dss original, produz um novo arquivo Master considerando os loadshapes gerados para cada load.

O script realiza uma varredura nos diretórios apontados, verifica a existência dos arquivos .dss que descrevem os diversos elementos que compõem o sistema, e gera os "Redirects"

  • INPUTS:
    • endereços para diretório que contém os elementos do sistema;
    • endereços para diretório contendo loads e loadshapes
  • OUTPUTS:
    • arquivo "MastersemPV.dss"
    • relatório.
